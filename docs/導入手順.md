# 導入手順(ローカルAI版)

事務所のパソコン1台に入れて使うまでの手順です。
すべての処理はそのパソコンの中で行い、書類の中身を外部に送ることはありません。

---

## 0. 用意するもの

| もの | 内容 |
|---|---|
| パソコン | Windows または Mac。メモリ16GB以上が目安(**【推測】** 資料によって8〜16GB以上と幅があるため、余裕を見た目安) |
| Node.js | 無料。[公式サイト](https://nodejs.org/ja)から「LTS(推奨版)」を入れる |
| Ollama | 無料のローカルAIソフト。[公式サイト](https://ollama.com/)から入れる |
| このフォルダ一式 | 事務所のパソコンの、分かりやすい場所に置く |
| 顧問先の一覧 | 顧問先コード・正式名称・略称・決算月。会計ソフトから書き出したCSVがあると早い |

インターネットが必要なのは、上のソフトとAIのモデルを最初に入れるときだけです。

---

## 1. ローカルAIのモデルを入れる(初回のみ)

Ollama を起動したあと、次のコマンドを実行します。
モデル名は例です。試験運用で、実際の書類を使って2〜3種類を比べて選んでください。

文字を読むモデル:

```bash
ollama pull qwen3:8b
```

スキャンした紙の書類も読む場合は、画像を読むモデルも入れます:

```bash
ollama pull qwen2.5vl:7b
```

---

## 2. 起動する

- Windows:`local` フォルダの **`起動_Windows.bat`** をダブルクリック
- Mac:`local` フォルダの **`起動_Mac.command`** をダブルクリック

初回は準備に少し時間がかかります。そのあと、ブラウザで操作画面が開きます。
黒い画面(起動したウィンドウ)を閉じると終了します。

安全のため、操作画面は**起動したときに自動で開いたブラウザでしか使えません**(同じパソコンを使う別の人は開けません)。
ブラウザを閉じてしまったときは、黒い画面で **Enter キー**を押すと、開き直せます。

起動したら、まず**導入チェック**で、必要なものがそろっているかを点検します(直し方も表示されます)。

```bash
npm run doctor -- --config local/config.json --full
```

`--full` を付けると、ローカルAIに実際に1件読ませて、1件あたりの時間も測ります。

## 2-2. 職員のパソコンから使う(事務所内LAN)

職員6〜30人の事務所では、処理用のパソコン1台で仕分けを動かし、職員は自分のパソコンのブラウザから使います。

1. 処理用パソコンの設定ファイル(`local/config.json`)に、次を書き足す

```json
"server": { "mode": "lan", "port": 8730, "hostnames": ["処理用パソコンの名前"] }
```

2. 操作画面を起動し直し、処理用パソコンで開いた画面の「設定」→「利用者」で、職員ごとの ID・名前・権限・はじめのパスワードを登録する
   - **管理者**:設定・利用者の管理・自動実行の変更ができる(所長・事務長など)
   - **職員**:仕分け・要確認の確定・除外ができる
3. 黒い画面に表示されたアドレス(例:`http://192.168.1.20:8730/`)を、職員のパソコンのブラウザで開き、ID とパスワードでログインする
4. 処理用パソコンのファイアウォールで、事務所内からのポート(8730)への接続を許可する

**安全のために**

- 事務所内のネットワーク(プライベートアドレス)以外からの接続は、自動で拒否します。
- パスワードを5回続けて間違えると、その ID は10分間ログインできません。
- 誰が・いつ・何をしたかは、保存先フォルダの `操作履歴.csv` に記録されます。
- **通信の暗号化(HTTPS)をおすすめします。** 証明書と鍵のファイルを用意し、設定ファイルに書き足します。

```json
"server": { "mode": "lan", "port": 8730, "tls": { "cert": "cert.pem", "key": "key.pem" } }
```

## 3. 事務所に合わせて設定する(画面の「設定」)

初回は「設定」が自動で開きます。

| 設定 | 内容 |
|---|---|
| 事務所名 | 画面の上に表示されます |
| 受付フォルダ | 職員がPDFを入れる場所。今の保存フォルダを指定してもかまいません |
| 保存先フォルダ | 仕分けたPDFと、一覧表(`書類一覧.csv`)を置く場所 |
| フォルダ名・ファイル名の付け方 | 事務所のいつもの付け方に合わせます。見本を見ながら決められます |
| 顧問先マスタ | 「CSVから読み込む」か、表に直接入力します。**略称(書類に出てくる呼び方)を別名に入れると、読み取りの精度が上がります** |
| 書類種別 | 使わないものはチェックを外します。事務所独自の帳票は「書類種別を追加」で足します |
| ローカルAI | 標準は「ルールで迷った書類だけに使う」 |
| スキャンした書類 | 紙をスキャンしたPDFも扱う場合はチェックを入れます |

最後に「設定を保存」を押します。

---

## 4. 精度を測る(本格導入の前に)

実際のPDFを50〜100件と、その正解表を用意して、どれくらい正しく仕分けられるかを測ります。
ファイルは動かしません。

```bash
npm run evaluate -- --config local/config.json --folder <PDFのフォルダ> --answers <正解表.csv>
```

正解表は、`local/正解表.template.csv`(見出しだけの空のひな形)に1件1行で書き足して作ります。
「**誤って自動仕分け:0件**」になるまで、表題の目印や顧問先の別名を足して調整します。

---

## 5. 毎日の使い方

1. 職員は、今まで通りPDFを受付フォルダに入れる
2. 「仕分け」タブで「試し実行」→「仕分けを実行」(管理者が自動実行を設定していれば不要)
3. 「要確認」タブで、PDFを見ながら書類種別・顧問先・期間を選び、表示された仕分け先を確かめて「確定して次へ」
   - 顧問先は、コードか名前を入力すると候補が出ます
   - 期間は、書類種別に合わせて「月」「決算期」「年」「日付」で入れられます
   - 同じ帳票がいつも同じ書類種別・顧問先になるときだけ、「次から自動で読めるように」にチェックを入れます
     (その帳票の表題や顧問先の呼び方を覚え、使うほど事務所の帳票に合っていきます)
   - 間違えて確定・除外したときは、直後に画面の下に出る「元に戻す」を押すと、書類が「要確認」に戻ります
     (直前の1件・10分以内。入力した内容は残ります)
4. 書類を探すときは「記録」タブで、顧問先・書類種別・月で絞り込み、「場所をコピー」してエクスプローラーなどに貼り付けます
5. 一覧表(`書類一覧.csv`)は、Excel や Googleスプレッドシートでも開けます
6. 月に1回、「記録」タブの「導入効果レポートを開く」で、自動で仕分けた割合と削減時間の目安を確認します

---

## 6. 困ったとき

| 状態 | 対処 |
|---|---|
| 画面に「ローカルAI:使えません」 | Ollama を起動する。モデル名が設定と同じか確かめる(ルールだけでも動き続けます) |
| 要確認が多い | 要確認の書類を確定するときに「覚える」を使う。顧問先マスタに略称(別名)を足す |
| スキャンした書類が読めない | 「設定」で文字起こしをオンにし、画像を読むモデルを入れる。JPEG以外の形式で保存するスキャナーには未対応(スキャナーの保存形式を「カラー/グレー(JPEG)」にする) |
| 画面が開かない・「この画面は開けません」と出る | 黒い画面で Enter キーを押す(新しいアドレスでブラウザが開きます。アドレスは5分間・1回だけ有効) |
| 「ファイルを移動できませんでした」と出る | そのPDFを開いているソフト(PDFビューアーなど)を閉じて、もう一度「仕分けを実行」 |
