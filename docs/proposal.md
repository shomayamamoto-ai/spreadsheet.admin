# 書類PDFの自動仕分け 導入のご提案

> 本資料内の表記ルール
> **【事実】** 出典のある情報 / **【一般】** 一般に知られていること /
> **【仮説】** 提案者の推測・見込み(実際の数字で要確認)

---

## 1. 現状の課題

会計ソフトなどで作成した書類をPDFにして保存していますが、
保存フォルダに**そのまま放り込んでいる**状態です。

その結果、次のような手間が発生しています。

- 後から「どの顧問先の・いつの・何の書類か」を、
  1件ずつ開いて確認しないと分からない
- ファイル名がバラバラ(例:`scan_0001.pdf`)で、検索しにくい
- 決算期や申告期限の前に、まとめて仕分け作業が発生する

**【仮説】** 仕分けに1件あたり1分かかると仮定すると、
月300件で**約5時間/月**の作業になります。
(実際の件数・時間は、事務所の実績で置き換えてください)

---

## 2. 解決策:PDFを「読んで」自動で整理する

```
受付フォルダにPDFを保存(今まで通り)
        ↓ 自動で読み取り(すべて事務所の中で処理)
書類種別・顧問先・対象期間・金額を判定
   ・まずルールで判定
   ・迷った書類だけ、事務所のパソコン内のAI(ローカルAI)が補う
   ・AIの答えは、根拠の文章がPDFにあるかを照合してから使う
        ↓
① 一覧表「書類一覧」に1行ずつ記録
② ファイル名を付け直し、フォルダへ自動で移動
   10001_株式会社さくら建設 / 2025年3月期 / 月次試算表 /
     10001_株式会社さくら建設_2025-03_月次試算表.pdf
③ 自信がないものは「_要確認」フォルダへ(人が確認して確定)
④ 同じ書類の二重保存は「重複の疑い」として止める
⑤ 顧問先ごとの「保存状況」シートで、保存漏れを一覧で確認
```

**ポイント**

- **職員の作業は今まで通り**「PDFを保存するだけ」。
  新しい操作を覚える必要がありません。
  要確認の書類だけ、操作画面でPDFを見ながら「書類種別・顧問先・期間」を選んで確定します。
- 一覧表(スプレッドシート)で、顧問先・書類種別・期間ごとに
  **絞り込み・並べ替え**ができます。
- 読み取りに自信がないものは自動で移動せず、
  **人の確認を必ず挟みます**(誤った場所に保存されるのを防ぐため)。
  直すときは、一覧表で書類種別・顧問先・期間を選び直して「確定」するだけです。
- **同じ書類を二重に保存した場合**は、自動では仕分けず「重複の疑い」として知らせます。
- **保存状況シート**で、顧問先ごとに「どの書類が未保存か」が一目で分かります。

| 項目 | 内容 |
|---|---|
| ブラウザ版デモ | PDFをドラッグ&ドロップすると、その場で読み取って一覧表と仕分け後のフォルダを表示(`demo/`) |
| サンプル書類 | 月次試算表・決算書・法人税申告書・消費税申告書・源泉所得税納付書・源泉徴収票・メモ、表記ゆれのある書類、重複した書類(架空データ9件) |

| 本番の原型① ローカルAI版 | 事務所のパソコンで動くプログラム(`local/`)。ルール+ローカルAI(Ollama)。ダブルクリックで開く操作画面つき(試し実行・仕分け・自動実行・要確認の確定) |

「(株)さくら建設」のように表記がゆれた書類も、
顧問先マスタと照合して正式名称・コードにそろえています。

※ サンプルの帳票は、一般的な会計帳票をまねた架空のものです。
特定の会計ソフトの帳票を再現したものではありません。

## 4. 仕組み(技術的な補足)

| 項目 | 内容 |
|---|---|
| PDFの文字の読み取り | ローカルAI版:パソコン内の部品(pdf.js)で取り出す。Google版:Googleドライブの変換機能(PDF→Googleドキュメント)を利用 |
| 内容の判定 | キーワードと書式のルールで判定(例:「月次試算表」「自 令和6年4月1日 至 令和7年3月31日」「顧問先コード」)。ローカルAI版は、ルールで迷った書類だけローカルAIが補う |
| AIの答えの検証 | 書類種別・顧問先は候補の中からだけ選ばせ、根拠の文章がPDFにあるか、顧問先の名前やコードを含むかを照合。日付は根拠の文章をルールでも読み直して突き合わせる |
| 重複の検知 | 顧問先・書類種別・対象期間が同じ書類が、すでに仕分け済みなら「重複の疑い」にする |
| 表記ゆれ対策 | 「顧問先マスタ」シートと照合し、正式名称・コードにそろえる |
| 和暦の扱い | 令和・平成の日付を西暦に変換して整理 |
| 実行タイミング | ローカルAI版:パソコンのタスクスケジューラで定期実行(例:15分ごと)。Google版:15分ごとの自動実行(時間主導型トリガー) |

- **【事実】** GoogleドライブではPDFを「Googleドキュメントで開く」ことで、
  文字をテキストとして取り出せます(スキャン画像の場合はOCR)。
  ただし表の多い書類では、レイアウトが崩れることがあります。
  (出典:[TechRepublic](https://www.techrepublic.com/article/how-to-extract-text-from-a-pdf-or-image-in-google-drive/))
- **【事実】** Google Apps Script は1回の実行が最大6分、
  トリガーの合計実行時間は1日あたり
  無料アカウントで90分、Google Workspace で6時間です。
  (出典:[Google Apps Script の割り当て](https://developers.google.com/apps-script/guides/services/quotas))
  → Google版は1回20件まで・5分で区切って処理するため、この範囲で動きます。
- **【一般】** 会計ソフトから直接出力したPDFは、通常は文字情報を持ったPDFです。
  紙をスキャンしたPDFよりも、読み取りの精度は高くなります。

## 5. 個人情報の守り方(ローカルAIで、中身を外に出さない)

顧問先の書類には、氏名・住所・マイナンバー・生年月日・口座などの
個人情報が含まれます。本仕組みは、読み取りの精度を上げるためにAIを使いつつ、
**書類の中身を事務所の外のAIやサーバーに一切渡さない**作りにしています。
「使わない」という約束だけでなく、**設定と自動チェックで保証**します。

### 2つの版

| | ローカルAI版(おすすめ) | Google版(AIなし) |
|---|---|---|
| 動く場所 | 事務所のパソコン | Googleのサーバー(Apps Script) |
| 読み取り方 | ルール+**パソコン内のAI**(迷った書類だけ) | ルールのみ |
| 外部への送信 | なし(通信先を「このパソコン自身」に限定) | なし(外部通信の権限を付けない) |
| 一覧表 | `書類一覧.csv`(Excel・Googleスプレッドシートで開ける) | Googleスプレッドシートに自動記録 |
| 操作 | ダブルクリックで開く操作画面(ブラウザ) | スプレッドシートのメニュー |
| 必要なもの | Ollama(無料のローカルAIソフト)と、メモリに余裕のあるパソコン | Google Workspace |

### 守り方

| 守り方 | 内容 | どう保証するか |
|---|---|---|
| ① AIは事務所のパソコンの中だけ | ルールで読めた書類はAIを使わない。迷った書類だけ、パソコン内のAI(Ollama)が補う | 外部のAIサービスを呼び出す処理がない |
| ② 外部へ送れない設定 | ローカルAI版は、通信先を「このパソコン自身(localhost)」に限定。Google版は外部通信の権限を付けない | 外部の住所を設定しても、プログラムが通信を拒否する。Google版は、Googleの権限の仕組みで送信できない |
| ③ AIの思い込みを採用しない | AIに「答え」と「根拠にした文章」を出させ、その文章が本当にPDFにあるか、顧問先がマスタにあるかを照合 | 確かめられない答えは使わず、「要確認」にする。ルールとAIの判定が違うときも「要確認」 |
| ④ 毎回の自動チェック | プログラムを直すたびに、自動テストで確認 | 外部への通信命令や権限が入ると、テストが失敗する |
| ⑤ 相談するときは伏せ字版だけ | 迷った書類を外部に相談したいときは、伏せ字にした文字だけをコピー | 氏名・住所・個人番号・生年月日・電話・メール・口座・会社名・事務所名・金額・よくある名字・事務所が登録した言葉を自動で伏せる |
| ⑥ 必要な項目だけ記録 | 一覧表には、書類の全文ではなく、種別・顧問先・期間・金額などだけを記録 | 全文は保存しない |
| ⑦ 共有設定の見張り | Google版は、フォルダやPDFが「リンクを知っている全員」に公開されていたら処理を止める | 公開フォルダでは動かない |

### 根拠となる事実

- **【事実】** Ollama は、パソコン内(`http://localhost:11434`)で動くローカルAIのソフトです。
  回答の形をJSONで指定する機能があります。
  (出典:[Ollama 公式ドキュメント Structured outputs](https://docs.ollama.com/capabilities/structured-outputs))
- **【事実】** Apps Script で外部と通信する機能(UrlFetchApp)は、
  `script.external_request` という権限がないと使えません。
  (出典:[Google Apps Script UrlFetchApp](https://developers.google.com/apps-script/reference/url-fetch/url-fetch-app))
- **【事実】** Google は、Google Workspace のデータを、許可なく生成AIの学習に使わないと公表しています。
  (出典:[Generative AI in Google Workspace Privacy Hub](https://support.google.com/a/answer/15706919?hl=en))
  **【推測】** これは法人向けの約束であり、個人の無料Gmailアカウントでは同じとは限りません。
  そのためGoogle版は、個人アカウントで設定すると警告を出します。
- **【事実】** 個人情報保護委員会は、生成AIサービスに個人情報を含む内容を入力する場合、
  利用目的の範囲内かどうかや、入力したデータが機械学習に使われないかなどを
  十分に確認するよう注意喚起しています(2023年6月)。
  (出典:[ScanNetSecurity の報道](https://scan.netsecurity.ne.jp/article/2023/06/13/49506.html)、
  [モノリス法律事務所の解説](https://monolith.law/corporate/ppc-ai-service-alert))
  → ローカルAI版は、データが事務所のパソコンから出ないため、この確認事項の多くが問題になりにくい構成です(**【推測】**)。

### パソコンの目安

- **【推測】** 必要なメモリは資料によって幅があり、
  70億パラメータ級(7B〜8B)のモデルで「8GB以上」とする資料も、「16GB以上」とする資料もあります。
  (出典:[StorageReview](https://www.storagereview.com/best/agentic-ai-hardware)、[valebyte](https://valebyte.com/en/blog/ollama-server-requirements-ram-vram-and-cpu-by-model-size/))
  余裕を見て、**メモリ16GB以上のパソコン**を目安とし、試験運用で速度を確かめます。
- **【推測】** 日本語に強いモデルは入れ替わりが早いため、モデルは設定で変えられるようにしています。
  試験運用で、2〜3種類を実際の書類で比べて選ぶ前提です。
  (参考:[crystal method の解説](https://crystal-method.com/?p=14418))
- AIを使うのは「ルールで迷った書類」だけなので、大半の書類はAIを待たずに処理されます。

### 正直にお伝えすべき限界

- ローカルAIは、クラウドの大型AIより精度が低いことがあります。
  そのため、AIの答えは「根拠の照合」に通ったものだけを使い、残りは人が確認します。
- 伏せ字機能は、見出しの無い珍しい名字の人名などを見落とすことがあります。
  伏せ字版も、渡す前に必ず人の目で確認する運用が必要です。
- 伏せ字にしても、書類の種類や時期などから、顧問先が推測される可能性はゼロではありません。
  外部への相談そのものを認めるかどうかは、事務所の規程で決める必要があります。

## 6. 導入ステップ(案)

| 段階 | 内容 | 目安 |
|---|---|---|
| ① 帳票の確認 | 実際によく使う帳票のPDFを5〜10種類お借りし、読み取りルールを調整 | 1〜2週間 |
| ② 試験運用 | 担当者1〜2名、顧問先数社で運用。要確認の割合を計測 | 2〜4週間 |
| ③ 本格導入 | 全顧問先へ拡大。顧問先マスタを整備 | 1〜2週間 |

ローカルAI版の場合は、①の前に「パソコンの準備(Ollamaとモデルの導入、速度の確認)」を半日〜1日見込みます。

**【仮説】** 費用は、Google Workspace を既に利用していれば、Google版の追加のシステム費用は原則かかりません。
ローカルAI版は、Ollama 本体は無料ですが、メモリが足りない場合はパソコンの増強・購入費用がかかります
(いずれも開発・調整の工数は別)。

## 7. 期待できる効果

- 仕分け作業の削減(**【仮説】** 要確認の割合を1〜2割に抑えられれば、
  作業時間は8割程度削減できる見込み)
- 書類の検索時間の短縮(顧問先・期間・書類種別で即座に絞り込み)
- 保存ルールの統一(担当者によるファイル名・フォルダのばらつきがなくなる)
- 保存状況シートで「どの顧問先の、どの書類が未保存か」をすぐ確認できる
- 二重保存に気づける(同じ書類が何枚もある状態を防ぐ)

効果の大きさは、デモ画面下の「効果の試算」に、
事務所の実際の件数と作業時間を入れて確認できます。

## 8. リスクと対策

| リスク・弱点 | 対策 |
|---|---|
| **守秘義務・情報管理**:顧問先の情報を扱う(**【事実】** 税理士法第38条で守秘義務が定められています。出典:[ウィキブックス 税理士法第38条](https://ja.wikibooks.org/wiki/%E7%A8%8E%E7%90%86%E5%A3%AB%E6%B3%95%E7%AC%AC38%E6%9D%A1)) | AIは事務所のパソコン内(ローカルAI)だけで使い、外部への通信はプログラムで禁止(5章)。Google版は外部通信の権限を付けず、公開フォルダでは動かない |
| **Googleドライブ利用の可否**:事務所の規程でクラウド保存が認められていない可能性 | 導入前に所内規程・セキュリティ方針を確認(**要確認**) |
| **読み取りミス**:書類種別や期間を間違える | 自信がないものは「要確認」に回し、自動では移動しない。AIの答えは根拠をPDFと照合し、確かめられないものは使わない |
| **パソコンの性能**:ローカルAIが遅い・動かない | AIは迷った書類だけに使う。AIが動かないときは、ルールだけで処理を続ける作りにしている |
| **帳票レイアウトの変更**:会計ソフトの更新で書式が変わる | 判定ルールを1か所(`DOC_TYPES`)にまとめ、修正しやすくしている |
| **既存機能との重複**:利用中の会計ソフト側に、同様の保存・管理機能がある可能性 | 導入前に、会計ソフトの提供元へ確認(**要確認**) |
| **スキャンした紙の書類**:画像のPDFは読み取り精度が下がる | まずは会計ソフトから直接出力したPDFに対象を絞る |
| **運用が属人化**:作った人しか直せない | 設定はスプレッドシート上で変更でき、手順書(README)を用意 |

**反対意見として想定されるもの**

- 「ファイル名のルールを決めて手で付ければ十分では?」
  → 件数が少ない事務所では、それでも十分な可能性があります。
  月の件数と、今の仕分け時間を測ってから判断するのが確実です。
- 「クラウドのAI(ChatGPTなど)のほうが精度は高いのでは?」
  → その可能性はあります。ただし、顧問先の書類を事務所の外へ送ることになり、
  守秘義務や契約条件の確認が必要です。本提案では、精度よりも
  「中身を外に出さない」ことを優先し、ローカルAIと人の確認を組み合わせています。
- 「ローカルAIでも、本当に外に出ていないと言い切れるのか?」
  → 通信先をプログラムで「このパソコン自身」に限定し、それを自動テストで毎回確かめています。
  さらに確実にしたい場合は、パソコンのファイアウォールで、このプログラムの外部通信を止める設定も併用できます。

## 9. ご確認したいこと

1. 月に保存するPDFのおおよその件数と、現在の仕分け時間
2. よく保存する書類の種類(上位5〜10種類)
3. 現在の保存先(Googleドライブ/社内サーバー/その他)
4. 理想のフォルダ構成(顧問先→年度→書類種別、でよいか)
5. 顧問先コードの一覧を、マスタとして使えるか
6. 生成AIの利用について、事務所の規程があるか(伏せ字版での相談を認めるか)
7. ローカルAI版を動かすパソコンのメモリ容量(16GB以上が目安)
