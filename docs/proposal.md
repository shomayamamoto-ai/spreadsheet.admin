# 書類PDFの自動仕分け 導入のご提案

> 本資料内の表記ルール
> **【事実】** 出典のある情報 / **【一般】** 一般に知られていること /
> **【仮説】** 提案者の推測・見込み(実際の数字で要確認)

---

## 1. 現状の課題

TKCのシステムで作成した書類をPDFにして保存していますが、
保存フォルダに**そのまま放り込んでいる**状態です。

その結果、次のような手間が発生しています。

- 後から「どの関与先の・いつの・何の書類か」を、
  1件ずつ開いて確認しないと分からない
- ファイル名がバラバラ(例:`scan_0001.pdf`)で、検索しにくい
- 決算期や申告期限の前に、まとめて仕分け作業が発生する

**【仮説】** 仕分けに1件あたり1分かかると仮定すると、
月300件で**約5時間/月**の作業になります。
(実際の件数・時間は、事務所の実績で置き換えてください)

---

## 2. 解決策:PDFを「読んで」自動で整理する

```
受付フォルダにPDFを保存(今まで通り)
        ↓ 15分ごとに自動で読み取り
書類種別・関与先・対象期間・金額を判定
        ↓
① スプレッドシート「書類一覧」に1行ずつ記録
② ファイル名を付け直し、フォルダへ自動で移動
   10001_株式会社さくら建設 / 2025年3月期 / 月次試算表 /
     10001_株式会社さくら建設_2025-03_月次試算表.pdf
③ 自信がないものは「_要確認」フォルダへ(人が確認して確定)
```

**ポイント**

- **職員の作業は今まで通り**「PDFを保存するだけ」。
  新しい操作を覚える必要がありません。
- 一覧表(スプレッドシート)で、関与先・書類種別・期間ごとに
  **絞り込み・並べ替え**ができます。
- 読み取りに自信がないものは自動で移動せず、
  **人の確認を必ず挟みます**(誤った場所に保存されるのを防ぐため)。

---

## 3. デモの内容

| 項目 | 内容 |
|---|---|
| ブラウザ版デモ | PDFをドラッグ&ドロップすると、その場で読み取って一覧表と仕分け後のフォルダを表示(`demo/`) |
| サンプル書類 | 月次試算表・決算書・法人税申告書・消費税申告書・源泉所得税納付書・源泉徴収票・メモ(架空データ7件) |
| 本番の原型 | Googleドライブ+スプレッドシートで動く Google Apps Script(`gas/`) |

**デモの結果**:サンプル7件中、6件を自動で仕分け、
1件(関与先・期間が書かれていないメモ)を「要確認」と判定。

※ サンプルの帳票は、一般的な会計帳票をまねた架空のものです。
TKCの実際の帳票とはレイアウトが異なります。

## 4. 仕組み(技術的な補足)

| 項目 | 内容 |
|---|---|
| PDFの文字の読み取り | Googleドライブの変換機能(PDF→Googleドキュメント)を利用 |
| 内容の判定 | キーワードと書式のルールで判定(例:「月次試算表」「自 令和6年4月1日 至 令和7年3月31日」「関与先コード」) |
| 表記ゆれ対策 | 「関与先マスタ」シートと照合し、正式名称・コードにそろえる |
| 和暦の扱い | 令和・平成の日付を西暦に変換して整理 |
| 実行タイミング | 15分ごとの自動実行(時間主導型トリガー) |

- **【事実】** GoogleドライブではPDFを「Googleドキュメントで開く」ことで、
  文字をテキストとして取り出せます(スキャン画像の場合はOCR)。
  ただし表の多い書類では、レイアウトが崩れることがあります。
  (出典:[TechRepublic](https://www.techrepublic.com/article/how-to-extract-text-from-a-pdf-or-image-in-google-drive/))
- **【事実】** Google Apps Script は1回の実行が最大6分、
  トリガーの合計実行時間は1日あたり
  無料アカウントで90分、Google Workspace で6時間です。
  (出典:[Google Apps Script の割り当て](https://developers.google.com/apps-script/guides/services/quotas))
  → 本仕組みは1回20件まで・5分で区切って処理するため、この範囲で動きます。
- **【一般】** TKCのシステムから出力したPDFは、通常は文字情報を持ったPDFです。
  紙をスキャンしたPDFよりも、読み取りの精度は高くなります。

## 5. 導入ステップ(案)

| 段階 | 内容 | 目安 |
|---|---|---|
| ① 帳票の確認 | 実際によく使う帳票のPDFを5〜10種類お借りし、読み取りルールを調整 | 1〜2週間 |
| ② 試験運用 | 担当者1〜2名、関与先数社で運用。要確認の割合を計測 | 2〜4週間 |
| ③ 本格導入 | 全関与先へ拡大。関与先マスタを整備 | 1〜2週間 |

**【仮説】** 費用は、Google Workspace を既に利用していれば
追加のシステム費用は原則かかりません(開発・調整の工数のみ)。

---

## 6. 期待できる効果

- 仕分け作業の削減(**【仮説】** 要確認の割合を1〜2割に抑えられれば、
  作業時間は8割程度削減できる見込み)
- 書類の検索時間の短縮(関与先・期間・書類種別で即座に絞り込み)
- 保存ルールの統一(担当者によるファイル名・フォルダのばらつきがなくなる)
- 一覧表を見れば「どの関与先の、どの書類が未作成か」も確認しやすくなる

## 7. リスクと対策

| リスク・弱点 | 対策 |
|---|---|
| **守秘義務・情報管理**:関与先の情報を扱う(**【事実】** 税理士法第38条で守秘義務が定められています。出典:[ウィキブックス 税理士法第38条](https://ja.wikibooks.org/wiki/%E7%A8%8E%E7%90%86%E5%A3%AB%E6%B3%95%E7%AC%AC38%E6%9D%A1)) | 外部のAIサービスにはデータを送らないルール方式を採用。処理は事務所のGoogleアカウント内で完結。フォルダの共有範囲を事務所内に限定 |
| **Googleドライブ利用の可否**:事務所の規程でクラウド保存が認められていない可能性 | 導入前に所内規程・セキュリティ方針を確認(**要確認**) |
| **読み取りミス**:書類種別や期間を間違える | 自信がないものは「要確認」に回し、自動では移動しない。一覧表で人が最終確認 |
| **帳票レイアウトの変更**:TKCのシステム更新で書式が変わる | 判定ルールを1か所(`DOC_TYPES`)にまとめ、修正しやすくしている |
| **既存機能との重複**:TKCのシステム側に同様の保存・管理機能がある可能性 | 導入前にTKCの担当者へ確認(**要確認**) |
| **スキャンした紙の書類**:画像のPDFは読み取り精度が下がる | まずはTKCから出力したPDFに対象を絞る |
| **運用が属人化**:作った人しか直せない | 設定はスプレッドシート上で変更でき、手順書(README)を用意 |

**反対意見として想定されるもの**

- 「ファイル名のルールを決めて手で付ければ十分では?」
  → 件数が少ない事務所では、それでも十分な可能性があります。
  月の件数と、今の仕分け時間を測ってから判断するのが確実です。
- 「AIで読み取ればもっと柔軟では?」
  → 精度は上がる可能性がありますが、関与先の情報を外部サービスへ送ることになります。
  守秘義務と契約条件の確認が必要なため、まずはルール方式で始める提案としています。

## 8. ご確認したいこと

1. 月に保存するPDFのおおよその件数と、現在の仕分け時間
2. よく保存する書類の種類(上位5〜10種類)
3. 現在の保存先(Googleドライブ/社内サーバー/その他)
4. 理想のフォルダ構成(関与先→年度→書類種別、でよいか)
5. 関与先コードの一覧を、マスタとして使えるか
